# Phase 043 characterization — Body 2D

Body 2D is an editor-authored component, separate from Phase 041 ordinary Collider 2D geometry and Phase 042 Trigger Collider 2D detection. The v1 data contract is a singleton `{version:1,enabled:true,type:'static'|'kinematic',linearVelocity:[x,y]}`. A Body may be authored without a Collider; validation warns because it cannot participate physically. A no-Collider Kinematic still follows its velocity. A Trigger does not count as a physical Collider.

The existing editor simulation loop clamps delta time to 0.1 seconds. Phase 043 inserts the Body manager after hierarchy/world-transform update and before the Trigger lifecycle. This gives a Trigger query the committed post-motion positions in the same tick. A Trigger remains detection-only and never obstructs a Body. Trigger callback edits to velocity take effect on the next Body tick.

The Body manager is a pure UMD module at `editor/src/00-body-2d.js` and reuses the existing Collider 2D shape resolver. It resolves enabled Static Body Box/Circle geometry once per tick, then processes enabled Kinematic Bodies in stable object order. Only enabled ordinary Colliders belonging to enabled Static Bodies obstruct. Static Bodies never move in the solver; Kinematic/Kinematic pairs have no response. A Body with multiple Colliders uses all valid shapes. The broad phase rejects Static shapes outside a swept AABB. Narrow-phase Box/Box SAT, Circle/Circle, and Box/Circle separation support rotated obstacles. X then Y axis-separated movement produces generic sliding. Conservative advancement locates a safe fraction on the sweep, with bounded iteration and a small contact tolerance, rather than accepting only the final pose; thin-wall/high-speed motion cannot leap over an obstacle in the qualified cases. Candidate IDs and hit IDs are deterministic. Requested `linearVelocity` is never overwritten by wall contact.

Velocity is world-XY units per second. Root motion changes local position directly. For parented objects, the world displacement is transformed by the inverse parent quaternion and parent scale before writing local Transform; a singular parent scale yields zero actual motion without NaN or a world-space jump. Direct Transform edits during Play are treated as teleports and are not automatically depenetrated; initially overlapping shapes are handled conservatively, with authored corrections expected. Play/Stop snapshots and restores the authored Body/Transform, including level switches. No runtime physics cache is serialized.

The Inspector exposes Static/Kinematic with Static velocity fields disabled, a plain-language response boundary, removal, Undo, and a warning on Body without an ordinary Collider. The Add Component registry exposes a singleton Body. Save/Load, duplication, Prefabs, Editable export, and Playable export preserve the component and behavior. Both export builders include the Body runtime module. The internal Phase 043 dogfood scene is not a public Game 29.

Scope is intentionally narrow: no Dynamic Body, gravity, mass, forces, impulses, friction, restitution, angular velocity, character controller, one-way platform, slope/step logic, moving-platform carry, collision filtering, Tilemap physics consumption, or general collision-event lifecycle. The named Phase 044/045/048/049 and Tilemap seams describe future work without implementing it.

Qualification artifacts live under `qualification/phase-043/`: 20 isolated browser cycles, 500,607 seeded movement cases, frame-partition and anti-tunneling fuzz, Body/Trigger checks, performance fixtures, and a completed 30.0034-minute active browser soak. The ready verdict rests on the completed soak and full regression gates, not on implementation alone.
