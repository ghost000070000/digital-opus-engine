## 5. First-person view obstruction — root cause and fix (Section 6A)

**Symptom**: Signal Relay, Arsenal Run, and Power Grid each showed a large flat-colored surface filling roughly the bottom third to half of the viewport during actual play.

**Diagnosis** (reproduced live, via direct scene inspection in the running standalone builds, not guesswork): the obstruction was the **Player's own First-Person collision body** — a primitive box entity (`firstPersonEntity`), confirmed by inspecting its live `position`/`color`/`scale`/`visible` state at runtime (color and scale matched the observed obstruction exactly).

**Root cause**: `spawnFirstPersonController` correctly sets `firstPersonEntity.visible = false` once at spawn ("FPS convention: never render your own body"). But `syncPlayerVisual()` — called every frame by the shared player-update dispatcher for *every* controller type — falls through to `teardownPlayerVisual()` whenever the active controller has no skinned visual (true for First-Person and Hovercraft). `teardownPlayerVisual()` unconditionally executed `player.entity.visible = true` every single frame, to restore the primitive body after a Third-Person/Top-Down skinned character visual is torn down. It did not check controller type, so for First-Person it silently re-showed the entire collision body on every frame of every First-Person game, permanently overwriting the spawn-time convention.

**Fix** (`editor/src/01-editor.js`, `teardownPlayerVisual`): the restore line now reads `if (player && player.entity && player.controllerType !== 'firstperson') player.entity.visible = true;` — Third-Person/Top-Down (the only controllers this restore exists for) are unaffected; Hovercraft's own always-visible craft body is unaffected; First-Person's body now correctly stays invisible for the entire session.

**Verified live** in rebuilt standalone builds of all three required games (Signal Relay, Arsenal Run, Power Grid): the obstruction is completely gone in all three, zero console errors. Foglight (Third-Person, uses the skinned visual path this restore line exists for) was also re-verified after the fix — its player character model is still correctly visible, confirming no regression.

## 6. Generic Crate Run controls text (Section 6B)

**Root cause**: the on-screen controls reminder was a single string hardcoded directly into `editor/index.html`'s markup (the original Crate Run demo's own hovercraft instructions — "WASD / Arrows to drive · Space to boost · Collect crates..."), shown by `spawnHovercraftController` on *every* Hovercraft-controller game regardless of what that game actually was. Confirmed this affected Survival Arena 2.0 and Survival Arena 3 (both Hovercraft-controller games about surviving hunter waves, not collecting crates).

**Fix**: added a new player-facing `controlsHint` field to the existing Start Screen config object (`currentUiConfig.startScreen`, alongside the already-established `howToPlay`/`credits` fields, same blank-hides-it convention), with a matching textarea in the Player Settings panel. The hint display was moved out of the Hovercraft-only spawn function into the one shared `spawnPlayer()` choke point every controller funnels through, so any controller type can now show an authored hint. **Default: blank** — none of the 28 existing projects has this field authored, so all of them now correctly show no hint at all, rather than another game's instructions. Verified live: Survival Arena 2.0 no longer shows any Crate Run text.

## 7. Identity consistency (Section 6C)

Added `identityMismatches()` to `build/build-games-site.js`: compares catalog title, project meta title, Start Screen title, and generated HTML `<title>`, and **fails the build for any entry reaching a public surface** (`onlyVisibility` builds only — an internal regression fixture's mismatched title never blocks anything).

**Explicit fix**: `games/relic-frontier.json` had `levels[0].name` and `levels[0].ui.startScreen.title` both set to "Relic Runner 2", while `meta.title` and the catalog said "Relic Frontier" — a real player would see "Relic Runner 2" as the actual on-screen heading while the browser tab said "Relic Frontier". Fixed both fields to "Relic Frontier". No other renaming or content change was made to this project — per this pass's own instruction, this fix alone does not make Relic Frontier public-quality (it remains `visibility: internal`, `purpose: mechanics-sample`, still has empty-room/primitive-geometry issues per Section 1).

## 8. Test-fixture protection (Section 6D)

Added `suspectedTestFixtureAssets()`: flags any `skinnedMesh` project asset with fewer than 24 vertices as a suspected engineering test rig, and **fails the build for any public entry using one**. This is a deliberately narrow heuristic (not a general asset classifier), sized to catch exactly the pattern already confirmed in this repo: `games/relic-frontier.json`'s own "IronSentry" asset is a 10-vertex, 2-joint flat ribbon — structurally identical to `tests/fixtures/skinned-bend.gltf` and `dogfood-assets/mist-guardian.gltf`, just inlined rather than referenced by file. Currently a no-op in practice (0 public entries to check), but will correctly block this exact asset the moment anyone tries to mark Relic Frontier public without replacing it.
