Digital Opus Creator Guide

Local, no-code-first 2D and 3D authoring. No account, model or telemetry service is required by this guide.

Generated from registered Components, Gameplay Presets, authoring language, built-in Actions and Graph Conditions. Bounded creator reference, not an exhaustive runtime API or a claim that every advanced tool is accessible.

Supported workflows and explicit limits

Make, test, save and share

  1. Open the editor. Choose Guided First Game · 3D or a playable 2D/3D starter. Creating a starter replaces the open document: save unsaved work first; named saved projects are kept.
  2. Select an Object. Inspector → Add Component attaches reusable data; Apply Gameplay Preset configures a role such as Collectible. Eligibility depends on the Object.
  3. For a pickup, apply Collectible and set its counter name. Add a matching Counter Display through UI/HUD controls. Play, collect it, check the visible counter, then Stop. Presets create ordinary editable data; review changes with Undo/Redo.
  4. Save a named Project locally. Reload and reopen it from Home to verify persistence. Save is not an online backup; transfer a full Project or Editable HTML to another device. See Saving, player progress and backups for the different stores.
  5. Select the complete assembly and Save Selection as Prefab. Place another instance and verify independent behavior. Saved Projects carry their included Prefab library: reopening restores those definitions, not another open Project's same-named definitions. It does not synchronize other saved Projects. Legacy Projects that omit a library may use the browser-local fallback. Asset Pack transfer is explicitly additive and preserves data/dependencies, not automatically installed executable host extensions.
  6. Export Editable Game retains authoring tools. Export Playable Game produces game-only HTML without editor access. Both require preflight review: fix blocking errors; warnings retain data. Confirm, open the downloaded HTML and test it independently.

Supported workflows and explicit limits

Common no-code 2D/3D creator routes use the existing Components, Presets, Graphs, starters, history, reusable Prefabs and portable exports. These are bounded workflows, not promises of every advanced engine feature.

  • 2D and navigation: use Sprite controllers, orthographic framing, Static/Kinematic/Character collision and authored Waypoint links. Pixel-perfect integer rendering, general Dynamic mass/forces/stacking, automatic navmesh, avoidance and reachability generation are not provided by those contracts.
  • Authoring and diagnostics: searchable tools and live State/AI observation plus bounded Graph Trace support common routes; advanced panels remain dense. No breakpoint/replay debugger, complete AI decision history or universal gameplay/typo validator is claimed. Test your intended gameplay after typed Problems/preflight review.
  • Names and reusable content: state names remain exact-case strings. Flag/Counter/Timer suggestions help reuse, not automatic global rename; Object Variable names remain separate. Prefabs retain name identity and explicit manual linked updates/parameters, not global GUID live-sync. Named Item/slot/Weapon/socket selectors retain unavailable legacy bindings; automatic bone/clip rename migration and socket scale inheritance are not claimed. Material Apply copies values; later library edits do not change placed copies automatically.
  • UI and animation: use HUD anchors, screen stacks/templates, explicit animation mappings/crossfades and ordered Sequence/Camera/Animation composition. There is no universal responsive free-layout canvas, general skeletal blend tree or multitrack Sequence scrub. Preview target viewports; physical gamepad/touch and assistive-technology compatibility require target-device testing, not assumptions from desktop automation.
  • Imports: staged reports and approval cover supported embedded glTF/GLB, images and browser-decoded Audio. Inspect warnings, Cancel or re-export unsupported content; original encoded files remain available. Universal codecs/PBR/morphs/external folders/transcoding and predecoder decompression-security guarantees are not included. Reports describe supported limits; some image/Audio limits apply after decoding.
  • World organization: use Scene filtering, visibility/collapse, Collections, Prefabs and Chunks at the demonstrated scale. Arbitrary bulk reparenting, scene locking and 100k-object performance are not guaranteed. Use separate Trigger Objects/grouped Prefabs for multiple volumes or separate Fog/Audio zone effects. Trigger Stay runs per tick; Circle bounds use the larger XY scale and targets require eligible Colliders. Layers/Masks filtering is supported.

These explicit limits are not hidden feature implementations. No account, cloud, model or telemetry service is required. For browser-local authoring versus portable files and shared runtime slots, read Saving, player progress and backups.

Saving, player progress and backups

Saving your game design and saving a player's progress are separate operations.

OperationWhat it keepsWhere to return
Save ProjectThe authored Project: levels, settings and reusable definitions. It does not capture a running playthrough.A named browser-local Project slot; reopen through Home in the same browser profile and origin.
Export Project JSON or Editable GameA portable authored Project for backup or further editing. Playable Game is the game-only delivery tier and may omit unused authoring assets.The downloaded file. Keep a separate copy; a download does not back up runtime save slots.
Save Game / Load GameSupported player progress and opted-in world state, not edits to the Project. Use the same named slot for saving and loading; an empty slot name uses default.Browser-local player-save slots. Autosave writes the auto slot only when your authored Action runs; Continue uses the runtime flow's saved-game controls.

Runtime slots use doengine:playersave:v1:PROJECT_ID within this browser origin. New projects and independent copies receive separate identities; exports and replacement restores preserve their project's identity. Two copies deliberately keeping the same identity share progress on the same origin. Choose Restore independent copy or Home Copy to separate them. Project JSON exports contain authored content, not runtime playthrough saves.

Older shared doengine:playersave records are never loaded or claimed automatically. Pause → Recover older progress offers an explicit non-destructive copy into this game only. Recognize the older slot before copying: its original project cannot be proved. Existing destination progress is not overwritten; the older record is kept.

Save Project reports Saved only after a verified local write of current authored content. Unsaved Changes, Saving, Save Failed and Storage Unavailable are distinct. Keep the page open after failure and use Back Up Project JSON; verify the downloaded file by restoring a copy. A download request does not prove a backup exists. Named Project saves use browser-supported Web Locks for cooperating-tab coordination; HTTPS/localhost and a supported browser are required for that safe local save path. Portable export remains available without it. Browser leave-page warnings are best effort and may be suppressed.

In the editor, named projects, their previous revision, local version history and the Prefab library are stored in IndexedDB, which holds far more than ordinary browser storage, and the editor asks the browser to keep that data persistent. Projects saved by older versions move there automatically the first time the editor opens. Preferences and runtime Save Game slots stay in ordinary browser storage.

Browser profile, site address and storage policy matter. A different origin or profile may not see earlier saves; file:// storage behavior varies by browser. Clearing site data, private browsing, blocked storage or quota limits can lose or prevent browser-local saves. Local history is not an off-device backup. Keep portable Project/Editable backups outside browser storage. No cloud sync or online backup is implied. Test Save Game, reload/Continue and recovery in the actual delivery environment.

Find controls and recover

Help provides contextual manual examples. Ctrl+K opens Editor commands: search Add Component, Gameplay Preset, Save Project or export. Escape cancels a dialog; visible Cancel/Close controls remain available. Select next/previous Object commands recover selection. Problems identifies structured references needing repair; it never silently deletes unavailable data.

Behaviors combine an Event and Action; Visual Graph handles branching; Sequence orders existing Actions. Custom Script and host Action extensions are advanced, separately trusted browser code, not required for ordinary authoring or a security sandbox.

Important boundaries

Physical screen-reader/tablet/IME support, native browser zoom and universal keyboard-only canvas workflows are not certified. Advanced visual tools may require pointing input. Registered data definitions do not imply every item is addable to every Object or every genre is ready.

Fields may have additional validation or context-dependent choices in the editor. Inspect the actual form and preflight. No runtime callbacks, private project content, capability grades or permission decisions are generated into this guide.

No-code vocabulary

Action

An operation requested by logic.

Behavior

A local reaction made from an Event, optional Conditions, and Actions.

Component

Reusable capability and data attached to an eligible Object.

Condition

A question that returns true or false.

Custom Script

The advanced code escape hatch for logic outside the curated vocabulary.

Event

Something that happened and can start logic.

Object

An entity placed in a scene.

Preset

A reusable composition that configures Components, Behaviors, and settings for a gameplay role.

Sequence

Ordered or time-based presentation and gameplay steps.

Signal

A named communication event for reusable, decoupled logic.

Template

A larger starting structure for a project, level, or genre.

Variable

Named state owned by a project, Object, or system.

Visual Graph

A graph for complex branching and state orchestration.

Event vocabulary

On Click

Runs when the Object is clicked.

Gameplay · click

On Controller State

Runs once when this level's Player enters a chosen resolved movement or grounding state. Blocked input is not movement; Airborne also includes walking off an edge.

Gameplay · controllerStateEvent

On Interact

Runs when the player uses Interact while in range.

Gameplay · interact

On Object Enter

Runs when a Physics Object enters this trigger area or lands on this object (a crate on a pressure plate, a ball in a goal).

Gameplay · objectEnter

On Object Exit

Runs when the last Physics Object leaves this trigger area or this object (the plate is released).

Gameplay · objectExit

On Signal

Runs once for each queued occurrence of the chosen named Signal on this active level. Repeated sends remain distinct.

Gameplay · signal

On Sprite Animation Event

Runs when one named frame event is entered by one specific Sprite Object and Clip.

Visual · spriteAnimationEvent

On Start

Runs when the level starts.

Gameplay · start

On Trigger 2D Enter

Runs once when an eligible Collider 2D Object enters this Object's Trigger Collider 2D.

Gameplay · trigger2DEnter

On Trigger 2D Exit

Runs once when an eligible Collider 2D Object leaves this Object's Trigger Collider 2D.

Gameplay · trigger2DExit

On Trigger 2D Stay

Runs once per simulation tick while an eligible Collider 2D Object remains inside.

Gameplay · trigger2DStay

On Trigger Enter

Runs when another Object enters this Object's trigger area.

Gameplay · enter

On Trigger Exit

Runs when another Object leaves this Object's trigger area.

Gameplay · exit

On Trigger Stay

Runs every frame while another Object remains in the trigger area.

Gameplay · stay

On Update

Runs once per active simulation tick. Paused, stopped and ended games do not dispatch it.

Gameplay · update
