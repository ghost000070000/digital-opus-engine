## Product result implemented

Three editable named Graph starters compose existing public no-code systems:
reusable key opens a closed Door/Gate while preserving the key; consumed key opens
then removes an explicit quantity; quest turn-in requires an **active** existing
Objective, completes it and removes the selected quantity. Named Item, Door and
Objective choices replace hidden-id memorization for this opt-in workflow.

Additive Has Named Item, Remove Named Item and Door Is Closed use the existing
inventory, Door/Gate state and Graph interpreter. Historical free-name Has Item,
Give Item and Remove Item retain their original semantics. No new item taxonomy,
quest runtime, automatic global key consumption, inventory store or Game29.

Eligibility is captured once into an invocation-local Boolean before effects.
Both effect and final consumption are gated on that value; consumption is last.
This handles repeated open-door/completed-quest interaction without consuming
remaining inventory. No delayed nodes, effect-success oracle or transactional
rollback is promised. Actions/Conditions remain ordinary editable graph nodes.

Templates change only an explicitly confirmed draft. Revert/Cancel preserve
project state; Save Graph commits changed content with one Undo. Named setup
preflight checks current placed owner, unique Item/target/Objective and strict
positive integer quantity. Typed Item diagnostics cover actual Graph, reusable
Function and saved Prefab owners, retaining saved identity and unavailable refs.
Shared Graph Save repairs refuse Play/stale owners and no-op history while
preserving Controller State Event validation and canonical Function identity.
