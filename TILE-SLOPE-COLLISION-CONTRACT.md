# Tile Slope Collision contract — Phase 047

Tileset schema v6 adds `collision.mode: "slope"` with `slope: "up-right" | "up-left"` and the existing Boolean `oneWay`. Earlier Tilesets migrate without changing their Full Cell, Custom Rectangle, None, or one-way collision semantics. New Tiles still default to None. The Tile Palette exposes Slope Triangle, direction, one-way status, and a matching triangular preview; invalid direction fails validation and safely resolves to no collision.

The triangle occupies the lower part of the whole cell. Up Right uses local bottom-left, bottom-right, top-right; Up Left uses bottom-left, bottom-right, top-left. Thus a non-square cell's actual world geometry—not a hardcoded 45°—determines steepness. Tilemap transforms, including rotation and mirroring, are applied before the Character's maximum-angle decision. The indexed Tile query returns synthetic stable IDs of the form `tile:<map>:<layer>:<x>:<y>` and a transient internal triangle; it does not create a per-cell Body, scene object, Prefab, or public Polygon Collider component.

Layer `collisionEnabled` controls physical participation independently of visual `visible` and `locked`. A hidden but collision-enabled layer still blocks. One-way slope Tiles permit upward and side passage for eligible Characters and catch only downward crossings of a walkable upper edge. Too-steep one-way slopes use solid fallback. Ordinary Kinematic Bodies do not gain general Tilemap physics. Slope metadata survives Tile/Tileset duplication, JSON history, project Save/Load, Chunks, bundles, Editable Export, and Playable Export through the existing Tileset dependency model.
