# Phase 009 Characterization

## Before

The editor booted into a sample-oriented experience. Twenty-eight examples and tooltips existed, but a new creator had no true-first-run choice, no guided first-game path, no resumable progress, no contextual Help system, and several dead-end empty states. Phase 001 recorded this as `AFR-0015`, HIGH and PERVASIVE, with Onboarding graded D/Poor.

## Product gaps reproduced

- A clean profile did not explain how to go from Palette placement to a playable export.
- Examples were useful reference material but required reverse engineering.
- Player creation was especially implicit because the Player is level-scoped and appears at Play time.
- Add Component, gameplay presets, and Playable Export were discoverable only after knowing which panel to open.
- Empty selection, component, behavior, asset, HUD, and scene states did not consistently identify the next action.

## Phase 009 boundary

The rehabilitation targets one short current-capability 3D journey. It does not add Sprites/2D, cloud state, analytics, a documentation platform, or a broad template catalog. Tutorial preference is not project data. Existing projects are replaced only after an explicit Blank/Guided/Restart choice, and named saves remain intact.

## Acceptance characterization

The clean-profile Edge dogfood creates one object, moves it, adds Health, applies Collectible, configures a Player, adds a counter HUD, plays, saves, reloads/resumes, and downloads a 1.31 MiB playable-only HTML. The observed path took 24 counted clicks/interactions and 9 authored outcomes in 6.5 seconds under automation; the human target remains 10–20 minutes. No new friction record was discovered.
